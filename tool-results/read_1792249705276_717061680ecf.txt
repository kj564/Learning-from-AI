 16784→**Port note (browser adaptation):**
 16785→1. The whole collision pipeline is **Y-first, then X, then Z** (the comment `// LAND FIRST, then x and z` is literal). Many naive ports do X/Y/Z in one pass — that produces different `onGround` results. The exact order matters because `onGround` is set from `yaOrg != ya && yaOrg < 0` BEFORE the X/Z clips, and `og` (a local "was-on-ground" snapshot) is captured at that exact point to gate the step-up block.
 16786→2. `level->getCubes(this, bb.expand(xa, ya, za))` returns a **reference to a reused `std::vector<AABB>&`** (see §27.13 — `boxes` is a member cleared each call). In JS, return a fresh array each call (no aliasing concern) OR cache-and-clear; the key is `getCubes` is called **twice** in `move` (once for the main move, once for the step-up retry), and the second call reassigns the same local `aABBs` reference. Don't share one array between the two calls.
 16787→3. The **step-up block** (`if (footSize > 0 && og && ySlideOffset < 0.05f && (horizontalCollision))`) re-runs the entire Y/X/Z clip pipeline with `ya = footSize` (a "step up" height), then compares squared horizontal travel `xaN²+zaN² >= xa²+za²` and keeps whichever path moved further horizontally. If the step-up didn't help, `ySlideOffset += 0.5f` (a counter that, once ≥ 0.05f, disables further step-ups until `ySlideOffset *= 0.4f` at the end decays it). This is the auto-jump mechanic. **Previous port OMITTED this entire block.**
 16788→4. `ySlideOffset *= 0.4f` runs every tick at the very end (line 338) — this is the decay that lets step-up re-trigger. Keep it.
 16789→5. `noPhysics` short-circuit: when true (e.g. ItemEntity/PrimedTnt in some states), just translate `bb` and recenter `x/y/z` from it, then return. No collision. **Do not run collision when `noPhysics` is true.**
 16790→6. Web slowdown (`isStuckInWeb`): `xa *= 0.25`, `ya *= 0.05`, `za *= 0.25`, and zeroes `xd/yd/zd`. One-shot (clears the flag).
 16791→7. Sneak edge-clamp: three `while` loops nudge `xa`/`za` by `d=0.05` toward 0 if no cube is found 1 block below the clone-moved box. The third loop handles the diagonal case (both xa and za nonzero). **The third loop is often dropped in ports — it must be kept; it's what prevents sneaking off ledges diagonally.**
 16792→8. After collision, `xd=0` if `xaOrg != xa` (and likewise yd/zd) — zeroes the velocity component that was blocked. **Previous port often skipped this, leaving "phantom" velocity into walls.**
 16793→9. Walk-distance / step-sound: `walkDist += sqrt(xm²+zm²) * 0.6`. Fence/fenceGate special-case: if the tile at the step point is air, look 1 block down and if it's a fence/fenceGate, treat that as the step tile (so you get the wood step sound on top of fences). `nextStep = ((int) walkDist) + 1`.
 16794→10. `entityInside` loop: iterates every tile overlapping the post-move bb and calls `tile->entityInside(level, x, y, z, this)` — this is how cacti damage, water pushes, etc. fire. Keep this loop.
 16795→11. Fire tile check at the end: `level->containsFireTile(bb)` → `burn(1)` and if not in water, `onFire++` (and if `onFire==0` set it to `20*15`=300). If not in a fire tile, `onFire = -flameTime` (cooldown). If in water and onFire>0, `onFire = -flameTime` (extinguish). `flameTime` and `fireTime` are separate fields.

 16909→### 27.4 — Entity::moveRelative (Entity.cpp:575-590) — EXACT
 16910→
 16911→```cpp
 16912→void Entity::moveRelative( float xa, float za, float speed )
 16913→{
 16914→        float dist = sqrt(xa * xa + za * za);
 16915→        if (dist < 0.01f) return;
 16916→
 16917→        if (dist < 1) dist = 1;
 16918→        dist = speed / dist;
 16919→        xa *= dist;
 16920→        za *= dist;
 16921→
 16922→        float sin_ = (float) sin(yRot * Mth::PI / 180);
 16923→        float cos_ = (float) cos(yRot * Mth::PI / 180);
 16924→
 16925→        xd += xa * cos_ - za * sin_;
 16926→        zd += za * cos_ + xa * sin_;
 16927→}
 16928→```
 16929→
 16930→**Port note (browser adaptation):**
 16931→1. **Early-out: if `sqrt(xa²+za²) < 0.01`, return immediately** (no acceleration). This is the "no input -> no drift" guard. **Previous port omitted the early-out**, causing input-less drift when `speed` was nonzero.
 16932→2. **Normalize-then-scale:** `dist = sqrt(xa²+za²)`; if `dist < 1`, clamp `dist = 1` (so small inputs don't get amplified). Then `dist = speed / dist` (so the final `xa *= dist` scales the *unit* input vector by `speed`). Net effect: input vectors of magnitude >=1 are normalized to magnitude `speed`; input vectors of magnitude <1 are scaled by `speed/dist` where `dist=1`, i.e. multiplied by `speed` directly (preserving their sub-unit direction). **This dual mode is critical** — `Mob::aiStep` passes `xxa/yya` which are already ±1 inputs from the AI, so they get scaled to exactly `speed`. **Previous port just did `xa *= speed` without the normalize — diagonal movement was sqrt(2)x faster.**
 16933→3. Rotation: `sin_ = sin(yRot * pi / 180)`, `cos_ = cos(yRot * pi / 180)`. Then:
 16934→   - `xd += xa * cos_ - za * sin_`
 16935→   - `zd += za * cos_ + xa * sin_`
 16936→   - Note: `xa` is **strafe** (left-right), `za` is **forward** (in the `travel(xa, ya)` call, the second arg `ya` is forward and becomes `za` here — wait, check the signature: `moveRelative(float xa, float za, float speed)` — the **second param is named `za`** but it's the **forward** input). In `Mob::travel`, the call is `moveRelative(xa, ya, ...)` where `xa`=strafe, `ya`=forward. So inside `moveRelative`, `xa` param = strafe, `za` param = forward. The world-space delta is:
 16937→     - `xd += strafe * cos(yaw) - forward * sin(yaw)`
 16938→     - `zd += forward * cos(yaw) + strafe * sin(yaw)`
 16939→   - This is the **standard Minecraft yaw-rotation matrix** with yRot measured in degrees, 0 = +Z (south?), increasing clockwise. **Previous port swapped sin/cos signs** -> mobs strafed backward.
 16940→4. `Mth::PI` and `Mth::RADDEG` are constants in the Mth util. `Mth::PI` is ~3.14159265 (`Math.PI` in JS is fine).
 16941→

 16943→- Missing `< 0.01` early-out -> drift when no input.
 16944→- Missing `if (dist < 1) dist = 1` clamp -> diagonal inputs were amplified sqrt(2)x.
 16945→- Rotation signs flipped -> forward/back swapped.
