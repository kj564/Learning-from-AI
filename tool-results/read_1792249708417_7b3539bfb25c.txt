   245→ 16784→**Port note (browser adaptation):**
   246→ 16785→1. The whole collision pipeline is **Y-first, then X, then Z** (the comment `// LAND FIRST, then x and z` is literal). Many naive ports do X/Y/Z in one pass — that produces different `onGround` results. The exact order matters because `onGround` is set from `yaOrg != ya && yaOrg < 0` BEFORE the X/Z clips, and `og` (a local "was-on-ground" snapshot) is captured at that exact point to gate the step-up block.
   247→ 16786→2. `level->getCubes(this, bb.expand(xa, ya, za))` returns a **reference to a reused `std::vector<AABB>&`** (see §27.13 — `boxes` is a member cleared each call). In JS, return a fresh array each call (no aliasing concern) OR cache-and-clear; the key is `getCubes` is called **twice** in `move` (once for the main move, once for the step-up retry), and the second call reassigns the same local `aABBs` reference. Don't share one array between the two calls.
   248→ 16787→3. The **step-up block** (`if (footSize > 0 && og && ySlideOffset < 0.05f && (horizontalCollision))`) re-runs the entire Y/X/Z clip pipeline with `ya = footSize` (a "step up" height), then compares squared horizontal travel `xaN²+zaN² >= xa²+za²` and keeps whichever path moved further horizontally. If the step-up didn't help, `ySlideOffset += 0.5f` (a counter that, once ≥ 0.05f, disables further step-ups until `ySlideOffset *= 0.4f` at the end decays it). This is the auto-jump mechanic. **Previous port OMITTED this entire block.**
   249→ 16788→4. `ySlideOffset *= 0.4f` runs every tick at the very end (line 338) — this is the decay that lets step-up re-trigger. Keep it.
   250→ 16789→5. `noPhysics` short-circuit: when true (e.g. ItemEntity/PrimedTnt in some states), just translate `bb` and recenter `x/y/z` from it, then return. No collision. **Do not run collision when `noPhysics` is true.**
   251→ 16790→6. Web slowdown (`isStuckInWeb`): `xa *= 0.25`, `ya *= 0.05`, `za *= 0.25`, and zeroes `xd/yd/zd`. One-shot (clears the flag).
   252→ 16791→7. Sneak edge-clamp: three `while` loops nudge `xa`/`za` by `d=0.05` toward 0 if no cube is found 1 block below the clone-moved box. The third loop handles the diagonal case (both xa and za nonzero). **The third loop is often dropped in ports — it must be kept; it's what prevents sneaking off ledges diagonally.**
   253→ 16792→8. After collision, `xd=0` if `xaOrg != xa` (and likewise yd/zd) — zeroes the velocity component that was blocked. **Previous port often skipped this, leaving "phantom" velocity into walls.**
   254→ 16793→9. Walk-distance / step-sound: `walkDist += sqrt(xm²+zm²) * 0.6`. Fence/fenceGate special-case: if the tile at the step point is air, look 1 block down and if it's a fence/fenceGate, treat that as the step tile (so you get the wood step sound on top of fences). `nextStep = ((int) walkDist) + 1`.
   255→ 16794→10. `entityInside` loop: iterates every tile overlapping the post-move bb and calls `tile->entityInside(level, x, y, z, this)` — this is how cacti damage, water pushes, etc. fire. Keep this loop.
   256→ 16795→11. Fire tile check at the end: `level->containsFireTile(bb)` → `burn(1)` and if not in water, `onFire++` (and if `onFire==0` set it to `20*15`=300). If not in a fire tile, `onFire = -flameTime` (cooldown). If in water and onFire>0, `onFire = -flameTime` (extinguish). `flameTime` and `fireTime` are separate fields.

   749→ 17288→   - Compute ground friction `friction`: default `0.91` (air); if `onGround`, start at `0.6 * 0.91 = 0.546`, then look up the tile 0.5 below `bb.y0` (`floor(bb.y0 - 0.5)`) and if non-air, replace with `Tile::tiles[t]->friction * 0.91`. (e.g. ice friction is 0.98 -> `0.98 * 0.91`; normal block friction 0.6 -> `0.6 * 0.91`.)
   750→ 17289→   - `friction2 = (0.6 * 0.6 * 0.91 * 0.91 * 0.6 * 0.91) / (friction³)` — this is the **"slipperiness ratio"** that compensates for the fact that the player's input is applied via `moveRelative` then `move` applies friction once. The numerator is the "reference" friction for a default block (`0.6³ * 0.91³` ~ 0.101), and dividing by the actual `friction³` means: if the ground is slipperier than default, `friction2 > 1` and you accelerate MORE (sliding); if stickier, `friction2 < 1` and you accelerate less. **This is the exact MC formula. Previous port used `walkingSpeed * friction2` but computed `friction2` wrong (often just `1/friction` not `1/friction³`).**
   751→ 17290→   - `moveRelative(xa, ya, onGround ? walkingSpeed * friction2 : flyingSpeed)` — `walkingSpeed` is a per-mob field (default 0.1 for Mob, see Mob.h). `flyingSpeed` is also per-mob (default 0.02). **On the ground, the acceleration is scaled by `friction2` to pre-compensate for the slip. In the air, just `flyingSpeed`.**
